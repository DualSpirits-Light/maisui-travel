# 第 9 阶段检查点：双线路更新下载

日期：2026-09-23

状态：本地开发、签名测试 APK 和模拟器回归完成；生产双线路实包验收留待第 10 阶段统一发布。没有创建 GitHub Release、上传 R2 APK、部署 Worker 或修改线上更新变量。

## 实现

- 更新弹窗采用居中圆角布局，展示版本、更新说明、GitHub（加速）与 Cloudflare 两条可用线路。提供立即更新、后台下载、跳过此版本，以及下载进度、取消、失败后重试或切换线路。短更新说明自动收起，长说明滚动；暗色模式截图已检查。
- GitHub 线路从同一份已验证元数据读取 Release 附件地址，按 gh-proxy 文档给公开资源加 `https://gh-proxy.org/` 前缀；代理连接失败、404 或限流时尝试直连。允许 GitHub 附件跳到签名的 `release-assets.githubusercontent.com` URL。元数据不接受任意代理或第三方 APK URL。
- Cloudflare Worker 增加独立 `UPDATES` R2 绑定和当前版本的只读 APK 端点。只有对象存在、大小及自定义版本/哈希元数据与发布配置一致，清单才展示 Cloudflare 线路。端点限定当前版本、最大 256 MiB、每 IP 每分钟请求数，支持 HEAD 和单段 Range。
- Android 以单个前台服务负责下载；通知显示线路、进度、完成和失败。前台弹窗可继续观察同一任务；取消完成后才可切线重试，避免同时下载两个 APK。后台下载需要可用通知，安装仍由用户点击并在系统安装器确认。
- 每次下载及重启后保留的已完成文件都检查 SHA-256、包名、版本号和当前应用签名；失败或取消清理临时文件。忽略按版本号保存，每天首次启动检查一次。
- 构建脚本支持只在测试构建中指定版本号；仪器测试可打包真实签名 APK 和另一个签名的 APK 作为安全回归样例。
