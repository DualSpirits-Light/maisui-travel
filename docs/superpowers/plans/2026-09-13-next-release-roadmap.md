# 下一版体验与管理后台改进：分阶段执行计划

日期：2026-09-13；基线：0.4.0；下一版暂定 0.5.0。

目标：修复用户列出的 20 项问题，完成实际服务验证、统一界面及管理员入口后统一发布。
技术：现有原生 Android Java、SQLite 快照、Cloudflare Worker/D1/R2。
需求来源：本任务用户的 20 项反馈；本文件不保存任何密钥。

## 执行约定

- 第 1、2 阶段已获用户授权并完成本地实现；后续阶段仍须逐阶段确认。
- 用户确认“继续”后只执行下一个阶段；每阶段完成后提供变更、验证结果、未解决事项，询问是否继续，然后停止。
- 用户说“暂停”立即停止安排后续工作；保存已完成修改、正在运行的操作、阻塞项及下一步。恢复时先读取阶段记录，不重复已完成部分。
- 阶段内拆成独立小项，保存检查点；若子 Agent 额度不足，由主 Agent 接手，不循环重试消耗额度。
- 子任务沿用用户已确认的分工：Luna 处理简单 UI/调试/构建，Terra 处理常规功能，Astra 处理架构和最终审查。
- 中途仅测试构建与隔离后端验证，不向现有用户发布半成品。线上必要迁移先备份并验证，最终统一部署发布。
- 每阶段记录状态于本目录对应检查点文件；任何密钥只保存在仓库外私有配置，不进入代码、日志、截图、备份或安装包。
