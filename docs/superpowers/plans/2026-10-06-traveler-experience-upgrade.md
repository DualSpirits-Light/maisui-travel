# 出游体验优化实施计划

> 执行方式：主 Agent 操作专用模拟器并整合；独立表单与账本任务并行实施。用户已授权自主选择优化方案和连续推进。

**目标：** 用兰州三日旅行的真实操作流程找出阻碍，把规划、临时调整与同行记账连成可验证的本地使用过程。

**设计依据：** docs/reports/2026-10-06-小红书调研与产品改进建议.md。优先做高频且能完整验收的改进，本轮不新增生产服务、不发布正式 Release。

**架构：** 保留 Java 原生界面、SQLite JSON 快照和高德优先策略。旅行草稿采用 Activity 状态恢复；时间调整采用分离快照、应用前冲突校验和单步撤销；AA 用稳定成员 ID 与整数分，不需要同行人安装应用。

## 任务与文件所有权

- [x] 主 Agent：专用 emulator-5580 体验现有版本，记录页面截图、操作结果、实际缺陷。
- [x] 表单 Agent：TripEditorUi 与专属测试。恢复名称、城市、日期、标签、住宿导入和展开状态；MainActivity 生命周期接入由主 Agent 完成。
- [x] 账本 Agent：Trip、TripStore、FinanceUi、AA 规则/UI，以及分享和备份引用链。均摊、付款人、部分参与人、实际结清记录；旧账不自动分摊，纯净分享剔除个人账本，独立导入正确重映射。
- [x] 主 Agent：MainActivity、ItineraryTimelineUi、StopReorderLayout、AiExploreUi 和新增行程操作类。修复删除确认取消关闭草稿；时间锁定、顺延预览、冲突提示和可撤销的地点/排序/批量调整。
- [x] 串行 Android 回归：新功能专项、原有完整回归及大字体/深色界面观察；验证原发布证书与本地 APK。
- [x] 独立最终 Review、修复剩余问题、更新上下文和交付本地测试包及实测报告。

## 关键验收

1. 删除确认取消不丢编辑内容；删除保存失败保持原数据，撤销不覆盖之后的更改。
2. 预约锁定不受顺延影响，跨午夜明确预览日期，不越过旅行天数；不把安排间隔当交通耗时。
3. 均摊尾差精确到分，付款人可以不参与；转账不重复计入旅行支出，旧费用保持原含义。
4. Activity 重建不丢旅行表单。预算未设置时不误报超支，大账本避免一次渲染全部记录。
5. 完整分享、纯净分享、备份恢复与冲突副本的 AA 字段和成员引用一致；不在源码/附件嵌入 Key。

## 边界

真实国内网络、真机 GPS/相机和在线地图鉴权与模拟器结果分别报告；不以模拟器替代这些证据。线上免安装协作、景区精确人数及完整订单夹不因参考帖出现就仓促上线。保留本次任务开始前全部已有改动和历史产物。
