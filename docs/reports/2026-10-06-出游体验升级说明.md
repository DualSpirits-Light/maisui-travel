# 麦穗旅序出游体验升级说明

本轮以“中国用户准备兰州三日游”为场景，在专用 Android 模拟器重新安装此前体验修复包，实际进入新建旅行、连续录入地点、编辑删除和账本页面；再用合成的中文旅行、费用与照片执行自动操作和回归。本报告区分手动观察、源码审查、离线业务验证与未验证的在线能力。

本地测试版本：**0.5.1-preview / versionCode 12**。没有创建 GitHub Release、部署 Worker 或改线上更新清单；沿用原应用安装证书。

## 本次体验结论

原界面的旅行优先、日程列表与持久添加按钮已经比之前容易使用，不需要再推翻导航。真正影响出游的障碍是：临时修改缺少恢复手段；预约与普通游玩不能区分；多人账目只能记总额；表单和删除确认存在状态丢失风险。此次围绕这些完整流程实施升级，没有照搬参考帖的颜色或把宣传功能当成已验证需求。

| 体验中的问题与依据 | 本次处理 | 使用效果 |
|---|---|---|
| 模拟器实际点编辑地点→删除→取消后，原编辑窗口消失 | 删除确认前保留编辑器；成功写入后才关闭，失败回滚 | 未保存的名称、备注和照片不会因取消删除丢失 |
| 旅行编辑没有注册状态保存；专项先红确认为缺少 saveState | 恢复原始输入、标签、导入住宿信息、错误、展开和滚动状态 | 页面重建后能继续填，无效输入仍需校验，不自动保存 |
| 预算选填却以 0 预算展示剩余/超支 | 没设置预算时明确提示“尚未设置预算” | 单纯记账不再被误认为超支 |
| 排序后连续新增采用列表最后一站，可能比实际最晚结束时间早 | 默认时间改按当天最晚结束衔接 | 手动调整顺序不再破坏录入节奏；这仍是安排时间，不是交通估计 |
| 时间调整不能保护预约，也没有可检查、可撤销的批量修改 | 增加预约时间锁定、提前/顺延预览、跨日校验和冲突提示 | 选择第几天后在“行程工具→调整当天时间”操作；锁定预约不移动 |
| AI 也可能修改已预约的时间 | 模型提示与确定性验证共同拒绝修改锁定日期、时间和时长 | 不依赖 AI 自觉遵守规则 |
| 地点、账单、排序和 AI 应用缺少撤销 | 成功保存后提供一步撤销；后续改动使旧撤销失效 | 恢复原 ID、费用、照片引用和关联；不覆盖之后的新数据 |
| 地图标点仅有同名标题，时间线主要跳外部导航 | 编号绑定稳定地点 ID，标点展示详情/导航/编辑；有坐标的卡片可在行程地图定位 | 不靠名称区分同名地点，不伪造缺失坐标 |
| 账本缺少成员、付款人与参与人的关系 | 本地虚拟成员、均摊、部分参与、付款人及实际转账记录 | 同行人无需安装、注册或接受邀请，一人可代记全队 |
| 多笔账单一次全部渲染，最多可能有 5000 笔 | 每次显示 30 笔，可加载更多；图表保留按需展开 | 页面初次构建负担有明确上限，未宣称真机帧率已测量 |
| 初次 AA 审查发现成员列表不刷新、结算弹窗叠加旧余额 | 保存后替换成员列表；重建结算前关闭旧窗口 | 旧建议不从后层弹窗重新冒出 |
| 连续弹窗专项复现关闭窗口后圆角样式回调崩溃 | 样式回调先检查窗口仍在显示且已挂载 | 快速关闭和切换弹窗不再操作失效窗口 |

## AA 的明确规则

- 金额全程用整数分。1.00 元三人均摊为 0.34 / 0.33 / 0.33 元，分摊结果持久保存，改名或改备注不会重新分配尾差。
- 付款人可以不参加消费；参与人可以只选择部分队员。停用成员保留历史，稳定 ID 不随称呼修改；同名成员以编号区分。
- 旧账单不自动分摊。只有主动勾选 AA 的费用参与结算，单人账单不增加表单负担。
- 实际转账与旅行消费分别计算，可记录部分付款；修改或删除消费后重新算余额，保留已发生的转账。结算建议不是支付操作。
- 本轮为平均分摊，不含指定份额、多币种、邀请认领或远程共同编辑。

## 分享与数据一致性

本地快照升级为 schema 3，仍读取 schema 1/2，避免旧客户端静默忽略新增账本字段。完整分享包含成员、费用份额和实际转账；纯净分享明确排除这些私人内容。独立导入、恢复冲突副本重新生成 ID，并同步重映射付款人、参与人和转账双方；正常恢复保留原稳定身份。

三天口令与临时图片清理规则保持。此次检查了本地后端源码不会按内部 schema 拒绝 ZIP，未上传个人旅行或宣称线上新账本口令已经实测。

## 验证与局限

当前包完整 Android 回归 455 项通过；新增功能专项正常及 1.3 倍字体各 61 项，1.3 倍字体下审计专项 70 项、录入专项 121 项通过；本地业务规则 125 项通过。最终结果在 [本轮检查点](../checkpoints/2026-10-06-travel-experience.md) 记录；历史版本成功不作为当前 APK 的通过依据。专项包括存储写入失败、删除取消与撤销、表单恢复、均摊尾差、部分结清、完整 ZIP 实际导入和备份副本去重。

原生地图的真实鉴权、地图点选和镜头效果仍需要 ARM 真机验证；离线标点业务测试不能替代这些。真实 GPS、相机、付费 AI、城市实时热力、大陆下载链路本轮未重新请求或验收。不会用合成数据描述当前景区拥挤程度。

下一轮高价值方向仍是待规划候选池、实际路程/缓冲的时间线校验、旅中今天/凭证夹和免安装查看；这些独立功能没有因出现于调研报告便匆忙添加或部署。本轮交付的是上述已实现的完整流程及对应本地测试包。
