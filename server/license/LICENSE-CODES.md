# 第八阶段：授权码查看、补发与状态恢复

本阶段仅在本地实现和验收。以下远端迁移、Secrets 配置和发布步骤留待第十阶段统一发布批准后执行。

## 现有授权如何保留

- `0006_license_code_vault.sql` 只增加三个可空列和独立审计表。既有 `licenses.code_hmac`、授权 ID、期限、设备、管理员、捐赠及分享记录不变，不涉及 Android 旅行数据库。
- 新码继续用原 `CODE_PEPPER` 计算 HMAC 查找，另以 AES-256-GCM 加密保存可查看副本。每次加密生成独立 96 位随机 IV，128 位认证标签；认证上下文绑定版本、授权 ID 和密钥 ID，密文不能搬到其他授权记录解密。
- 旧码仅有单向 HMAC，无法还原。查看返回 `409 LEGACY_CODE_UNAVAILABLE` 并记录审计。不要把 HMAC 当授权码提供给用户。
- “补发独立新码”必须提交 `{confirm:true}`，创建新的授权 ID，复制原期限、设备上限、离线策略以及吊销、冻结、归档状态。原记录、原码、设备凭据全部保留，旧码继续按原规则激活和刷新；新记录的设备数从 0 开始。
- 补发不是续期或解冻，也不会自动迁移设备。管理员和使用者可主动改用新码；确认迁移完成前不要吊销或删除旧记录。新旧授权会同时占有各自设备额度，后台必须明确展示独立记录。
- 服务端保留旧 MS2 客户端协议与初始化前旧管理员令牌的过渡规则，避免让仍在使用旧版 App 的用户失效。管理员密码初始化后，旧管理令牌已由第七阶段规则自动禁用。移动端入口清理不等于删除已有授权数据。

## Secrets 配置和密钥生命周期

新增两项服务端配置，均可通过 Cloudflare Worker 的 Secrets 管理或交互式 `wrangler secret put` 写入；不能写进仓库、命令行参数、日志、截图、安装包或普通数据库备份：

| 名称 | 内容 |
| --- | --- |
| `CODE_ENCRYPTION_KEYS` | JSON 对象，以密钥 ID 映射到密码学安全随机生成的 32 字节 AES 密钥的标准 Base64 字符串；结构示意为 `{"key-2026-09":"<32-byte-random-key-in-base64>"}`。示意值不能用于部署。 |
| `CODE_ENCRYPTION_KEY_ID` | 当前写入密钥的 ID，例如 `key-2026-09`。只允许 1–64 个字母、数字、下划线或短横线。 |

密钥必须独立生成，不能复用 `CODE_PEPPER`、签名私钥、管理员密码或恢复凭据。保存在受控密码管理器的密钥托管记录，与 D1 数据备份分离，限制可读权限。

轮换时先向 `CODE_ENCRYPTION_KEYS` 添加新 ID/新随机密钥并保留所有旧项，再切换 `CODE_ENCRYPTION_KEY_ID`。新增授权使用新密钥，查看旧授权按其 `code_key_id` 读取旧密钥。密钥 ID 不得复用来覆盖旧值。检查新码签发/查看、旧码查看及旧设备刷新后再结束维护。

当前没有批量重加密工具。只要数据库或受保留备份还有记录引用旧 ID，就必须保留对应旧密钥；不能靠切换当前 ID 就删除旧密钥。密钥丢失会使相应副本无法解密，但不影响原 HMAC 激活和设备刷新。密钥泄漏时须评估该密钥下所有码是否泄漏，受控补发、主动迁移并按实际需要吊销旧码；简单切换密钥无法使已泄漏的码失效。

缺少密钥、格式错误、密文损坏或密钥不匹配时，签发/补发/查看返回 `503 CODE_VAULT_UNAVAILABLE`。现有授权的激活、刷新及期限管理继续工作；不能回退为明文存储。

## 管理 API 与状态语义

以下请求均经过现有管理员鉴权和限流；浏览器写操作仍要求同源 Origin。所有返回均 `Cache-Control: no-store`。错误结构为 `{error:{code,message}}`。

| 操作 | 接口 | 行为 |
| --- | --- | --- |
| 查看原码 | `GET /admin/licenses/:id/code` | 返回 `{id,code,codeStatus:"available"}`；先写审计再返回明文，审计写失败时不返回码。 |
| 补发独立码 | `POST /admin/licenses/:id/reissue`，`{confirm:true}` | 201，返回新 `id`、`sourceLicenseId`、`code`、`codeStatus` 和 `originalLicensePreserved:true`。 |
| 吊销后恢复 | `POST /admin/licenses/:id/restore-use` | 清除吊销及归档标志，保留冻结状态和期限。冻结仍须解冻，过期仍须续期。 |
| 冻结/解冻 | `POST /admin/licenses/:id/freeze` 或 `/unfreeze` | 有限期限暂停并在解冻时顺延；永久保持永久；吊销或归档记录须先恢复使用。 |
| 续期/永久互转 | `PATCH /admin/licenses/:id`，`{expiresAt,offlineSeconds}` | 字段可单独提交；`null` 为永久，有限值单位为秒。冻结中改期限会同步更新剩余时长，不自动解冻或解除吊销。 |
| 归档/取消归档 | `POST /admin/licenses/:id/archive` 或 `/restore` | 仅吊销记录可归档；取消归档仅恢复显示，保留吊销状态。 |

授权列表只增加 `codeStatus`（`available`/`legacy-unavailable`）和 `sourceLicenseId`，不包含码、HMAC 或密文。`available` 表示存在密文，实际解密仍可能因服务端密钥缺失而失败。

`license_code_audit` 保存授权 ID、管理员标识、动作、结果和时间，不保存明文、密文、会话令牌、密码或 IP。成功查看、历史码不可恢复、解密配置失败均留记录；未经鉴权的请求不会访问码。审计表不级联删除，以便在授权被管理员永久删除后仍保留查看记录。签发与补发属于创建操作，明文只返回给该管理员请求；列表与公开接口不返回明文。

并发期限/离线字段修改各自保留最新字段；冻结/解冻按写入时期限计算。归档和删除在写入时仍要求已吊销，避免与“恢复使用”竞争时隐藏或删除正在使用的授权。

## 备份、迁移、发布与回滚

1. 正式维护前暂停后台写操作，在仓库外受限目录导出现有 D1，记录 Worker 版本、迁移版本和授权/设备/管理员/捐赠表行数。沿用 [第七阶段备份与账户恢复步骤](ADMIN-ACCOUNTS.md)，同时核对密钥托管完整。备份本身不包含 Cloudflare Secrets。
2. 在隔离数据库依次加载 0001–0006；验证旧 HMAC、设备凭据和关联不变、旧记录新列为 NULL、旧码仍可激活刷新。先准备服务端独立密钥，再验证新码的签发、查看、审计、补发及所有状态转换。
3. 获准发布后先应用增量迁移再部署 Worker；不能在未迁移数据库上运行新版本。配置密钥项后验证管理员登录、旧码不可逆提示、新码查看、补发保留原授权、旧设备刷新和公开接口隔离。
4. 失败时优先回滚到第七阶段 Worker，保留新列和审计表及全部密钥。第七阶段代码仍能用相同 HMAC 和设备凭据激活/刷新，额外列不会影响旧 SQL；其间新签发码仅有 HMAC，会被下次升级识别为历史不可恢复码。
5. 不要删除列、审计表、整个数据库或通过全库覆盖丢弃发布后的数据。若必须还原数据库，先额外导出当前库，与发布前备份逐项核对新增授权/补发/设备/审计数据并制定合并方案。

本地回归使用 Node SQLite 执行真实 SQL 和 WebCrypto，不代表真实 Cloudflare D1/Workers/TLS 已验证。本阶段没有执行远端迁移、配置 Secrets、部署或发布。
